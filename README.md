# PonyOni Studio

Статический сайт-портфолио для команды PonyOni Studio. Проект использует HTML, CSS и JavaScript и готов к публикации через GitHub Pages.

## Локальный просмотр

1. Скачайте или клонируйте репозиторий.
2. Откройте `index.html` в браузере.

Для локального сервера (необязательно):

```bash
python -m http.server 8000
```

Затем откройте `http://localhost:8000`.

## Публикация через GitHub Pages

1. Создайте на GitHub новый репозиторий, например `ponyoni-studio`.
2. Загрузите в него все файлы и папки из этого проекта. Файл `index.html` должен лежать в корне репозитория.
3. Откройте **Settings → Pages**.
4. В разделе **Build and deployment** выберите **GitHub Actions**.
5. Откройте вкладку **Actions** и дождитесь завершения workflow `Deploy PonyOni Studio to GitHub Pages`.
6. Адрес опубликованного сайта появится в **Settings → Pages**.

При каждом push в ветку `main` сайт будет обновляться автоматически.

## Как заменить демонстрационные изображения

Сейчас карточки портфолио и галереи на страницах категорий содержат демонстрационные заглушки. Чтобы поставить свои работы:

1. Поместите изображения в `assets/portfolio/`.
2. В `index.html` найдите блок создания карточек портфолио (`portfolioGrid`) и замените декоративный контент на `<img src="assets/portfolio/имя-файла.png" ...>`.
3. Для изображений в галерее категории измените разметку `pageGallery` в функции `renderRoute()`.
4. Используйте относительные пути вида `assets/portfolio/model.png`, чтобы сайт корректно работал на GitHub Pages.

Рекомендуемые форматы: WebP или JPG для артов, PNG для изображений с прозрачностью, MP4/WebM для коротких демонстраций риггинга (видео лучше оптимизировать перед загрузкой).

## Что нужно настроить перед публикацией

- Заменить ссылки `https://t.me/` и `https://vk.com/` на ваши реальные контакты.
- Добавить реальные изображения и видео работ.
- Указать цены и условия каждой услуги.
- Вставить окончательный текст оферты.
- Проверить формулировки и контактные ссылки на мобильном устройстве.

## Важно

Внутренние страницы категорий реализованы как клиентская навигация по адресам вида `#service/full-model`. Такой вариант совместим с GitHub Pages и не требует отдельного серверного backend.
